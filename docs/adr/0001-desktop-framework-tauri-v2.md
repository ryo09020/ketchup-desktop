# ADR-0001: デスクトップアプリ基盤に Tauri v2 を採用する理由

## ステータス
承認 (Accepted)

## コンテキスト
KetchUp はもともと Web アプリケーション ([ketch-up](../../../ketch-up)) として React + TypeScript で開発されていました。
しかし、Web アプリのタイマーには以下の制約があります：
1. **ブラウザのリロードやタブ閉じでタイマーが中断・消失するリスク**
2. **バックグラウンドタブでのタイマースロットリング** (ブラウザの省電力機能により `setInterval` 等が遅延する)
3. **メニューバー（トレイ）常駐や、他作業中でのグローバルショートカット・即時タスク追加が困難**
4. **ネイティブ通知の権限管理やサウンド再生の制限**

ユーザーは React によるフロントエンド開発経験が豊富ですが、デスクトップアプリ開発の経験がありません。また、将来的に Mac App Store への公開を視野に入れています。

## 比較検討した選択肢

| 項目 | Tauri v2 | Electron | Flutter Desktop | Native (Swift / SwiftUI) |
|---|---|---|---|---|
| **フロント資産の流用** | ◎ React/Vite をそのまま利用可能 | ◎ React/Vite をそのまま利用可能 | ✕ Dart で完全再実装 | ✕ Swift で完全再実装 |
| **バイナリサイズ** | ◎ ~15MB (OS標準WebKitを利用) | ✕ 150MB~250MB (Chromium同梱) | ◯ 40~60MB | ◎ ~10MB |
| **アイドル時メモリ消費** | ◎ ~40MB | ✕ 150MB~300MB | ◯ ~80MB | ◎ ~30MB |
| **タイマーの堅牢性** | ◎ バックグラウンドでRust側スレッド稼働 | ◯ Node.jsプロセスで稼働 | ◯ Dartスレッド | ◎ GCD / Swift |
| **App Store 審査 (Sandbox)** | ◎ 審査通過実績多数・完全サンドボックス対応 | △ 巨大バイナリとプライベートAPI検知リスク | ◯ 通過可能 | ◎ Apple公式推奨 |
| **学習コスト** | ◎ UIはReact、ネイティブ機能はプラグイン | ◎ ほぼWebと同様 | △ Dart/Flutter習得が必要 | ✕ Swift/SwiftUI習得が必要 |

## 決定
**Tauri v2 (Rust + React + Vite + TypeScript)** を採用します。

### 決定の論理的根拠
1. **既存の React 資産を最大活用できる**
   ketch-up で作成された SCSS Modules、テーマ設計、コンポーネント構造、SWR によるデータフェッチロジックをスムーズに移行できます。
2. **圧倒的な軽量性と常駐アプリ適性**
   ポモドーロタイマーは「作業中常に起動してメニューバーに常駐する」性質を持ちます。Electron は Chromium エンジン全体を起動するため常時 200MB 以上のメモリを消費しますが、Tauri は macOS 標準の WKWebView を使用するため数十MBで動作し、Mac のバッテリーを消費しません。
3. **Rust によるミリ秒精度のタイマー**
   UI スレッドが重い処理やレンダリングを行っていても、Rust 側のバックグラウンドワーカーが正確なカウントダウンを保持し、OS ネイティブ通知を発行できます。
4. **App Store 審査ガイドラインへの適合**
   Tauri v2 は Apple の App Sandbox、公証（Notarization）、Hardened Runtime に正式対応しており、Mac App Store への提出がスムーズです。
